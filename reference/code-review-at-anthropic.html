代码评审速查手册

把原文压缩成可检索的术语、数字与关卡表。术语在此定义，所有课程严格遵守。

来源：How the Claude Code team does code review（2026-10-15）

一句话主张

评审的目标不是「有没有人读过代码」，而是「这次改动可能出什么错，以及哪一道检查适合拦住它」——把人的注意力留给只有人能判断的部分，同时用回滚率与事故率证明质量没有下降。

关键区分

评审有两个职责：①上线前发现并修复问题（本系列主线）；②在团队内传播代码库理解（最后一课谈）。原文明确说，自动化主要替掉的是第一种读取。

一次改动的七层关卡

层关卡拦什么是否阻塞
1提交前自验证（测试 / 构建 / 截图对比）+ 新上下文 subagent 复审 diff常规错误、与自己声明的目标不符否（PR 之前）
2每个 PR 的 AI 评审（读全仓 + PR 意图，多 agent 并行、投票去噪）根因未解决、破坏系统、风格/诊断类噪声被过滤发现须回复，未解决不能合并
3安全评审（独立一轮）安全问题是，发现未清不能合并
4自动检查：lint、类型、多平台测试、构建机械性回归；PR 模板要求写测试方式与回滚方式是
5按风险分级的人工审批需要人判断的部分（见下表）按风险等级
6合并队列 + 功能开关 + 渐进发布两个各自通过的 PR 合并后弄坏 main；对用户的爆炸半径是（队列重跑全部检查）
7快速发现与回滚（遥测、内部先用、每周 on-call）漏网之错；事故复盘追问「本该哪一层拦住」事后兜底

层的逻辑：每层拦住一部分、漏掉一部分，少数能穿过全部；剩下的交给回滚。不是一道闸门，而是层层过滤加兜底。

人工审批的风险分级

风险典型改动人工审批
低文档、文案、仅内部功能、开关后的增量改动自动评审与安全检查全绿后，无需人工
中普通产品改动；缓存、自动更新器、系统提示词等敏感区一人
高最高风险代码，以及少量固定路径两人

定级规则：由分类器读改动内容定级，不是作者自己选；第二个分类器再问「这次是否额外需要一个人」。固定路径（owner 标记的敏感区、CI workflow 文件）永远要人。只有可信名单上的作者能走轻量通道；agent 的批准不算人的批准；谁发起 agent 改动谁占一个评审名额；审批只覆盖当时的那个 commit，新 commit 需重新批准。

让评审收敛（核心机制）

作者是 agent 时，噪声成本更高：人可以几秒忽略一个 nit，agent 却会真的去改，于是多一个 commit、多一轮评审。作者与评审者都是 agent 时可能无限互相触发。

  • 轮数上限：3 轮后评审者请作者退后重审方案，而不是继续抠细节。
  • 前几轮之后只复审新 diff，不再全文重扫。
  • 标注 bug 的类别，让作者一次修掉所有同类，而不是改一行。
  • 不重复已发表过的发现。

诊断数据git blame 显示，反复标记的内容里约 59% 是评审者第一次评审时就存在的旧代码——评审者不是在发现新 bug，而是每轮多翻出一点旧的。这正是「评审必须收敛」的证据。

让评审者更好的闭环

  • 事故即 eval：把过去引发事故的 PR、修复与回滚收成评测集，每天跑；评审者的每次改动都要对全套重新打分。
  • 用人的行为测噪声：按人对每条评论的处理分类——修了 / 说不对 / 说有意如此 / 说无所谓；也在已知干净的 PR 上跑，统计会导致有害改动的误报。
  • 优先级写下来：先抓真 bug，再减少评审轮数。
  • 漏了就补输入：问「模型当时没看到什么」，把答案写进 CLAUDE.md、skill 或新检查，而不是只改一句提示。
  • 夜间全仓扫：评审 agent 每晚扫既有代码，提前抓旧 bug。

人留在哪里

  • 决定要不要做：方向、品味、范围；有团队即使宣称评审瓶颈已解，仍对来自团队外的改动保留人工评审，只因要问「我们该做这件事吗」。
  • 评审高风险代码：计费、自动更新器、CI workflow。
  • 评审架构：会被别人照抄的模式。
  • 读证据：测试输出、实际执行的命令与返回、截图、评审发现；说不出检查会漏什么时，要的是真评审而非快批。
  • 承担结果：每个上线的改动都有人负责，不论谁敲的键盘。

「你落地，你负责」与知识传播

中小改动出问题，团队规范通常是落地者自己修。前提是：改动小、一切可逆（开关/回滚/分阶段）、爆炸半径决定审查强度、回归能被快速发现、事故复盘对事不对人。

机器读了大部分 diff 之后，团队不再指望谁有完整心智模型；想理解某块代码就让 Claude 生成针对那一切片的 explainer，甚至做一个可视化小产物。开放 Slack 频道让旁路学习者看到别人在做什么。

成本指标与护栏指标

类别指标作用
成本（要降低）每 PR 人工审批数（中位数 / P95）、人工评论数、PR 等人的时长衡量省下多少人的时间
护栏（不许恶化）回滚率、事故率防止「省下的时间」只是转移到事后修坏代码

未决原文说目前没有「指标恶化时自动收紧审批」的断路器，团队希望在更多代码走向零人工合并之前先有它。

术语本文中的含义
