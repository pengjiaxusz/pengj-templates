# 语言变体文件 架构规范

> **索引定位**：对应 [`docs/architecture/README.md`](./README.md) 第 2 节「核心子系统与领域模块」。
> 定义「代码类产物按语言拆文件」的权威边界与命名契约。
> 本文是架构约束说明，不是 CLI 使用手册。

---

## 1. 问题背景

模板的多语言最初只有一种手段：**行内 minijinja 分支**

```jinja
{% if options["skill_lang"] == "en" %}English text{% else %}中文文案{% endif %}
```

这对**文档与注释**足够（渲染结果只留一种语言），但对**代码**是错的：

`templates/lefthook/commitlint.base.js` 曾把「中文校验模式」和「英文校验模式」两套判定
写在同一份脚本里，靠运行时参数 `lang` 选择。于是：

- 英文项目的脚本里永远躺着一段 `lang === 'zh'` 的分支——**永远不会执行的死代码**，
  且带着中文报错文案；
- 中文项目同样躺着一整段英文判定逻辑；
- 两个方向的代码互相干扰：改一处要同时顾及另一语言的用例，review 时噪音大。

这与仓库既有约定「**文档双语，代码不双语**」冲突。行内分支解决不了它，因为分支的是
**整段逻辑**，不是一句文案。

---

## 2. 契约：语言变体文件

同一份逻辑按语言各写一版**完整的**文件，生成时二选一，产物路径去掉语言标记：

| 命名 | 跟随的语言轴 | 典型用途 |
| :--- | :--- | :--- |
| `<stem>.<lang>.<ext>` | `skill_lang`（文档/文案轴） | 脚本、配置、YAML 等跟项目文案语言走 |
| `<stem>.commit.<lang>.<ext>` | `commit_zh`（提交语言轴） | 提交校验类脚本（如 `commitlint.base`） |

- `<lang>` 只认 `zh` / `en`；其他末段标记不触发变体解析，文件按原名输出。
- 命中语言的那份写到 `<stem>.<ext>`；**未命中的那份完全不落到项目里**。
- 两条轴互相独立：「中文文档 + 英文提交」时，文档类变体取中文、提交类变体取英文。

示例（`templates/lefthook/`）：

```
commitlint.base.commit.zh.js   ─┐
commitlint.base.commit.en.js   ─┴─►  commitlint.base.js（按 commit_zh 二选一）
```

实现位置：`crates/core/src/engine.rs::resolve_language_variant`，在
`build_file_map` 收集阶段生效——**先解析变体、再做技能过滤与文件分类**，
因此普通文件、拼接文件（`.gitignore`）、JSON 并集文件（`package.json`）一致适用。

---

## 3. 不变式

1. **产物无标记**：项目里不会出现 `*.zh.js` / `*.commit.en.js`，`manifest` 记录的也是
   去标记后的真实路径，`update` / `audit` 语义完全不变。
2. **单向取舍**：一个路径在某层里只应存在一个语言的变体；同时存在 `foo.zh.js` 与
   `foo.en.js` 时按各自语言各取一份，互不覆盖（后层同名覆盖规则照旧生效）。
3. **文档仍走行内分支**：`.md` 等文档用 `{% if %}` 分支（渲染后只留一种语言），
   不拆文件——拆了会让托管块与技能接管逻辑失去单页契约。
4. **中文分支逐字节稳定**：变体文件的 zh 版改动同样要满足「zh 渲染结果与改动前一致」，
   避免存量中文项目整体漂移。

---

## 4. 新增一个语言相关脚本的步骤

1. 按语言写两版完整文件，命名为 `<stem>.<lang>.<ext>`（或 `.commit.<lang>.<ext>`）。
2. 两版逻辑保持等价，只差文案与语言判定方向；不要在一版里保留另一语言的死分支。
3. 在 `crates/core/src/engine.rs` 的端到端测试里补断言
   （参考 `language_variant_files_pick_matching_language` 与
   `skill_lang_drives_every_generated_file_language`）。
4. 若脚本由项目侧配置引用（如 `commitlint.config.js` 引 `./commitlint.base.js`），
   引用的仍是**去标记后的路径**，无需改动。
