# 排队层与增量加层 架构规范

> **索引定位**：对应 [`docs/architecture/README.md`](./README.md) 第 2 节「核心子系统与领域模块」。
> 定义 `just` / `bque` 分层装配、`justfile` 托管块契约、层-技能联动与存量项目增量加层的权威边界。
> 本文是架构约束说明，不是 CLI 使用手册；用法见根目录 `README.md` 与 `templates/README.md`。

---

## 1. 问题背景

排队能力原先散落在三处且互不联动：

1. `templates/bque/` 是**空标记层**（只有 `layer.toml`，不产出文件）；
2. `templates/rust*/justfile` 用 `{% if "bque" in layers %}` 条件渲染出排队配方，
   且 `justfile` 被列入 `update_ignore`（种子文件，`update` 永不接管）；
3. `templates/agent/.agents/skills/bque/` 由 `options["skills"]` 独立勾选，与层无关。

由此产生：非 Rust 项目勾 `bque` 层拿不到 `justfile`、存量项目无法随模板演进排队配方、
层与技能两个开关组合出「半接入」、以及「给存量项目加层」缺少正规入口（`update` 只按
manifest 已有层重渲染，`adopt --force` 会全量重纳管）。

---

## 2. 分层装配契约

| 层 | 产出 | 依赖 | 职责 |
| :--- | :--- | :--- | :--- |
| `just` | 根 `justfile` | `common` | 唯一主入口：`set shell`、`default`、条件 `import`、托管块边界与项目专属区 |
| `bque` | `just/bque.just` | `common`, `just` | `queue-*` 自省/自愈、`queue-doctor` 自检、`q-run` / `q-bench` 通用包装 |
| `rust` | `just/rust.just` | `common`, `just` | 单 crate 的 `build/check/test/bench/fmt/ci` |
| `rust-workspace` | `just/rust-workspace.just` | `common`, `just` | 工作区版同套配方 |

- **主 justfile 必须唯一**：任何语言层都不得再产出根 `justfile`（后层覆盖会破坏条件装配）。
- **框架区/项目区**：根 `justfile` 的 `# PENGJ_TEMPLATE_START` … `# PENGJ_TEMPLATE_END`
  （Hash 风格，`crates/core/src/block.rs` 已支持）之间为框架区，`update` 原位替换；
  块外为项目专属区，永久保留。`justfile` 因此**不得**进入任何层的 `update_ignore`。
- **条件装配**：框架区按 `layers` 决定是否 `import 'just/bque.just'`；
  语言模块由 `options["just_recipes"]` 控制——`"rust"` / `"workspace"` 显式指定、
  `"none"` 关闭（已有自定义编排的项目只接入排队基础设施）、未设置时按所选层自动推断。
  存量老项目迁移时显式写 `"none"`，避免其自定义 `build` 与模块配方重名。
- **模块语法**：`just/*.just` 只含 recipe 与 `[windows]` / `[unix]` 属性，不写 `set shell`；
  `{{ARGS}}` 在模板里用 `{% raw %}` 包裹以免被 minijinja 提前求值。

## 3. 平台边界

bque 是 **Windows 全局内核锁**。所有 `[unix]` 分支的等价行为是：

- `q-run` / `q-bench` 直接透传命令；
- `queue-*` 控制面打印明确提示，不假装存在队列。

因此 CI（Linux runner）与 Unix 开发机上同一批 `just` 配方裸跑属**预期行为**，
文档与 AGENTS.md 红线必须写明该例外，严禁在 Unix 上强行套用原生 bque CLI。
`queue-doctor` 负责探测 `PATH`、回退 `$env:LOCALAPPDATA\bque\bin` 并给出一键安装命令。

## 4. 层-技能联动与半接入巡检

排队能力需要「可执行配方 + Agent 行为规范」两者同时在位。`ensure_queue_skill`
在 `generate` / `adopt_project` / `update_project_with_options` / `add_layers_to_project`
四处统一生效：当解析后的层含 `bque`、模板提供 `bque` 技能、且 `options["skills"]`
为非空显式列表时，自动把 `bque` 并入并持久化。显式空列表（`[]`）表示用户明确不要技能，
此时不注入。

`audit_project` 新增非阻断 `warnings` 字段，报告两类配置漂移，不计入 `has_violations`：

1. 已启用 bque 层但技能清单缺 bque（半接入）；
2. 根 `justfile` 缺少 `PENGJ_TEMPLATE` 托管块（尚未迁移，update 无法同步框架区）。

## 5. 增量加层

`add_layers_to_project(templates, dir, new_layers, options)`：

1. `ProjectManifest::load` 读取 manifest，合并去重层清单；
2. `resolve_layers` 校验未知层 / 循环依赖，并让依赖层自动进入清单（如 `bque → just`）；
3. 按第 4 节补齐联动技能，写回 manifest；
4. 调用 `update_project_with_options` 按新层重渲染，复用其全部合并语义
   （托管块替换、JSON/TOML 结构化合并、冲突判定、哈希基线刷新）。

相较 `adopt --force`，该流程不重建 manifest、不覆盖项目专属区，是「给存量项目加入排队」
的唯一正规入口。CLI 暴露为 `add-layer --dir <项目> --layers just,bque`。

## 6. 存量项目迁移路径

已有自定义 `justfile` 的项目按以下顺序迁移，顺序不可颠倒：

1. 把原 `justfile` 改造为「托管块框架区 + 块外项目专属区」；
2. 删除项目区内与 `just/bque.just` 重名的 `queue-*` 四件套（等价能力由模块提供），
   其余项目自有 recipe 全部保留；
3. 在 manifest 写入 `options["just_recipes"] = "none"`（有自定义编排时）；
4. 运行 `add-layer --dir <项目> --layers just`，由 `update` 刷新框架区、
   创建 `just/*.just` 模块并重建哈希基线；
5. 用 `just --list` 与 `audit` 验证无重名 recipe、无半接入告警。

**反例**：直接在无托管块的 legacy `justfile` 上跑 `update`，会把整个托管块追加到文件末尾，
造成 `queue-*`、`build` 等配方重复定义，`just` 解析直接失败。
