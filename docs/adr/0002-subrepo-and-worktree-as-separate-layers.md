# 子仓库能力与多工作树能力拆成两个独立层

模板需要支持两类正交的宿主形态：一类宿主依赖由外部独立仓库提供的子仓库（以 git submodule 的形式接入），另一类宿主用多个 git 工作树并行开发、需要在工作树间共享编译产物目录。

我们把这两项能力**拆成两个独立可勾选的层**，而不是合并成一个「并行开发基础设施」层。

## Status

accepted

## Considered Options

- **合成一个层**：两者的交汇点只有一处——新开的工作树需要把子模块补齐。但它们的机制完全不同：子仓库能力是关于「外部仓库如何被引入与受控升级」，多工作树能力是关于「本地构建产物如何在多份检出之间复用」。合成一层会让只想用其中一项的项目被迫拿到另一项的全部产物。
- **先做子仓库、暂缓工作树**：子仓库能力有现成的技能与脚本可以承接，工作树能力则要从零设计。分批推进是可行的排期选择，但不改变「两者是并列关系」这个结论。

## Consequences

- 两层各自独立，`depends` 都只指向公共层与配方入口层，互不依赖。
- 交汇点（为新工作树补齐子模块）通过仓库初始化入口承接：该入口本就已经负责工作区链接与子模块补齐，两层各自调用它，不互相依赖。
- 「多工作树能力」这个名字容易让人以为它只管工作树。它同时提供共享编译目录，因此层的说明文本必须把两者都讲清楚，不能靠名称暗示。
